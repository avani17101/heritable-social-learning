# Heritable social-learning priors

**Can evolution discover a useful way to learn from others—and pass that
learning strategy to the next generation?**

![Learning within a life and selection across generations: fresh newborn, lifetime learning, held-out evaluation, then selection and mutation of the inherited prior. Only the genome is transmitted.](docs/figures/learning-prior-cycle.svg)

*Every birth resets neural weights and memories. The genome controls how the
newborn learns from evidence. [Download PNG](docs/figures/learning-prior-cycle.png).*

This research prototype explores Avani Gupta's idea of giving artificial agents
a compact, heritable learning prior. A newborn receives noisy private information
and imperfect evidence from a peer. Its inherited strategy shapes how much it
learns from each source and how selectively it trusts social information.

Only the genome crosses generations. Every newborn starts with fresh neural
weights, no memories, and no inherited optimizer state. The experimental cycle is:

**Inherited prior → lifetime learning → performance → selection → next generation's prior.**

The first genome has three parameters: private-evidence strength, social-evidence
strength, and trust selectivity. Keeping the mechanism this small makes it
possible to test the information problem analytically and compare evolution
against a tuned fixed strategy before introducing richer developmental rules.

## What this tests

The main question is whether a selected learning prior improves adaptation in
fresh newborns, including when private and social information change reliability.
The strongest comparison is against an independently tuned fixed prior. Better
performance than random genomes alone does not establish an advantage of
evolutionary search.

The task uses four hidden states and noisy, delayed social information. In an
analytical check, combining two 70%-reliable sources with a noisy peer-reliability
cue achieves 80.208% Bayes accuracy. No observation identifies the state with
certainty. The neural experiment uses 20 independent evolutionary seeds,
32 agents per population, and 50 generations.

This studies a **heritable social-learning strategy**. It does not demonstrate
cumulative culture. Peers are exogenous demonstrators, and shuffling genomes
among interchangeable newborns preserves population-level inheritance; that
control cannot establish a special causal role for lineage continuity.

## Current result

The corrected 20-seed study finds a useful evolved prior relative to random
genomes and individual-only learning. It does **not establish superiority over
the tuned fixed prior**: mean lifetime regret is 88.20 versus 87.83, with a paired
95% interval for fixed-minus-evolved regret of −0.98 to +0.19. Lower is better.

The baseline screening bug is fixed, all 21 tests pass, and the full rerun selected
the same baseline and reproduced the results. The original study is archived.
The rerun uses previously examined test seeds; it corrects the implementation
and is not an independent confirmation.

## Research to do next

- [ ] Match search budgets, candidate replication, and the effective parameter domain.
- [ ] Select both approaches on the same lifetime-learning objective.
- [ ] Test robustness to uninformative peers and miscalibrated reliability cues.
- [ ] Intervene on actual genome transmission, beyond shuffling lineage labels.
- [ ] Confirm on untouched seeds before expanding to richer genomes or culture.

The [full roadmap](docs/RESEARCH_ROADMAP.md) gives the purpose and decision criteria
for each experiment.

## Run locally

From the repository root, create and activate a Python 3.12+ virtual environment,
then install the recorded dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r heritable_social_learning/requirements-lock.txt
cd heritable_social_learning
python scripts/smoke_test.py
```

Use the technical README for baseline tuning, full experiments, transfer replay,
and provenance checks. Existing results are preserved by default; choose a new
`--output` directory for another run. All computations run on CPU.
